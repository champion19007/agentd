Agentd System Architecture

Agentd is designed around a single core tenet: deterministic execution must remain isolated from probabilistic AI inference. When an AI model fails, hallucinates, or goes offline, observation and scheduling must continue unabated.

1. Hexagonal Boundaries (Ports & Adapters)

The architecture strictly enforces clean directional boundaries. The deterministic core (internal/core) contains pure domain logic and is mathematically prevented from:

  • Importing concrete adapters (no net/http, no database/sql, no os).
  • Reading the system wall clock (time is injected via ports.Clock).
  • Calling non-deterministic random functions (entropy is injected via ports.Random).

2. Separation of Semantic Intent & Fragile Binding

Conventional scrapers couple "what I want" with "how I find it" into an unstable selector string. Agentd explicitly separates them into two distinct invariants:

The Intent (Permanent Semantic Contract)

The operator declares the immutable semantic structure they care about:

  • ScalarIntent: A single typed observation (e.g. Price as currency, Available as boolean).
  • RecordIntent: A named struct of semantic attributes (e.g. Title, Author, Rating).
  • CollectionIntent: A sequence of recurring records (e.g. Search results table).

The Binding (Ephemeral Implementation Detail)

The concrete locator (e.g. CSS selector .fare-box > span.val) used to fulfill the intent on today's HTML DOM. When the website redesigns, only the Binding breaks; the Intent remains unchanged.

3. Hash-Gated Model Triage (Zero-Token Invariant)

Every retrieved snapshot is hashed at two layers:

  1. Raw Payload Hash (SHA-256): Exact byte-for-byte stream digest.
  2. Canonical DOM Hash: Stripped of cosmetic comments, whitespace, nonces, and session tokens.

If the DOM hash matches the previous successful snapshot, the run is classified as quiet immediately. Zero LLM calls are made, eliminating token costs and preventing API latency.

4. The 5 Multi-Layer Sanity Verification Gates (G1–G5)

When an extraction fails, Agentd formulates candidate repair locators. To prevent hallucinations from ever reaching a human operator, every candidate is subjected to five automated verification gates:

  • Gate 1 (Structural Syntax): Rejects invalid CSS syntax, blank extractions, oversized payloads (>64 KB), and pseudoprotocol injection attacks (e.g. javascript:, data:).
  • Gate 2 (Shape & Type Consistency): Verifies that the candidate extraction matches the defined Intent type (e.g. parses as a currency float rather than free-form prose).
  • Gate 3 (Historical Stability): Re-evaluates candidate against historical known-good snapshots to verify consistency across previous DOM redesigns.
  • Gate 4 (Independent Semantic Verification): The candidate repair generator cannot verify itself. An independent model prompt with isolated context evaluates semantic fidelity.
  • Gate 5 (Field Continuity): For record and collection intents, ensures multi-field relative structures remain cohesive.

5. Mandatory Human-in-the-Loop Sign-Off

By foundational architectural invariant:

Invariant: Repair is NEVER automatically applied.

Autonomous self-modifying code leads to compounding hallucination loops and silent data corruption. Agentd presents verified candidates, but activating a new binding requires an operator signature via agentd repair approve <id> --by <name>.

6. SQLite WAL Concurrency & Storage

Agentd persists all data in embedded SQLite using WAL (Write-Ahead Logging) mode:

  • Single Dedicated Writer: Enforces strict serial transactional state updates without lock contention.
  • Multi-Connection Reader Pool: Readers never block writers, and writers never block readers.
  • Atomic Live Backups: Uses SQLite VACUUM INTO to generate clean checkpointed single-file backups while the daemon is actively serving traffic.
  • Deduplicated zstd Compression: Identical snapshot bodies across runs and checks are content-addressed and stored once using high-ratio zstd compression.
